# tests: 단위 테스트

이 폴더에는 `src`와 `experiments`의 코드를 검증하는 테스트가 들어 있습니다. 진행 계획서의 표 12에 정한 통과 기준을 테스트로 옮긴 것입니다.

## 실행 방법

`codes` 폴더에서 다음 명령을 실행합니다. 전체 실행에는 약 20초가 걸립니다.

```bash
python -m pytest
```

파일 하나만 실행하려면 경로를 지정합니다.

```bash
python -m pytest tests/test_csa.py
```

## 파일별 검증 내용

| 파일 | 검증 내용 |
|---|---|
| `test_instance.py` | 파서가 모든 구역을 올바르게 읽는지, 9,600개 파일이 모두 형식에 맞는지(모든 작업에 적격 기계가 있고, 모든 기계에 처리할 수 있는 작업이 있으며, 값의 범위가 생성 규칙과 일치하는지) |
| `test_schedule.py` | 완료시간과 총 지연이 손으로 계산한 값과 일치하는지, 유효성 검사가 누락, 중복, 비적격 배정을 찾아내는지 |
| `test_insertion.py` | 삽입 연산의 결과가 모든 위치를 직접 시도한 결과와 일치하는지, 동점 처리 규칙을 지키는지 |
| `test_h5.py` | 손으로 계산한 예제의 결과, 보정 단계의 동작, 벤치마크에서의 유효성, 최적값보다 작지 않은지 |
| `test_csa.py` | 이웃 연산자, VND, 무작위 이동(수용체 편집), 제한 목록의 크기, 거리, 적합도, 우선도, 재선택의 동작과, CSA_t가 H5보다 나쁘지 않은지, 같은 시드에서 같은 결과가 나오는지, 최선값이 세대가 지나도 나빠지지 않는지 |
| `test_sa.py` | 온도 설정과 냉각 방식 3종, 무작위 이동 1,000회에서 증분 평가와 전체 재계산이 일치하는지, 결과가 H5보다 나쁘지 않은지 |
| `test_milp.py` | MILP의 최적값이 6작업 인스턴스의 전수 탐색 결과와 일치하는지, MILP의 해를 평가 함수로 계산한 값이 목적함수값과 같은지 |
| `test_budget.py` | 시간 제한 계산식과 실행 예산의 동작 |
| `test_tiebreak.py` | 동점 처리 기준 네 가지가 삽입 연산, H5, GRASP, 이웃 연산자에서 정해진 대로 고르는지, 기준 `first`가 기준을 도입하기 전의 결과와 같은지, 실행기와 집계(`analyze_tiebreak.py`)의 동작 |
| `test_experiments.py` | 실험 실행기의 결과 행, 이어서 실행하기, 최적값 검사, 지표(RPD, RDI, 도달 비율) 계산 |
| `helpers.py` | 테스트용 보조 함수: 손으로 계산할 수 있는 예제(`tiny_instance`), 최적값이 0보다 큰 인스턴스 목록(`HARD`), 전수 탐색(`brute_force_optimum`) |

## 알아 둘 점

- Gurobi가 설치되어 있지 않거나 라이선스를 사용할 수 없으면 `test_milp.py`는 자동으로 건너뜁니다.
- 벤치마크의 다수는 최적 총 지연이 0이어서 H5만으로 최적해가 나옵니다. 탐색 과정을 검증하는 테스트는 `helpers.HARD`에 적어 둔, 최적값이 0보다 큰 인스턴스를 사용합니다.
- 같은 시드에서 같은 결과가 나와야 하는 테스트는 반복 횟수 기준의 실행 예산(`Budget(max_iters=...)`)을 사용합니다. 시간 제한 기준의 실행은 컴퓨터의 속도에 따라 결과가 달라질 수 있습니다.

## 다른 폴더와의 관계

- `src`와 `experiments`의 함수를 불러와 검증합니다. 다른 폴더는 이 폴더를 불러오지 않습니다.
- `data`의 인스턴스 파일을 `src/instance.py`를 거쳐 읽습니다.
- `results` 폴더에는 아무것도 기록하지 않습니다.
