# src: 알고리즘 모듈

이 폴더에는 문제의 자료 구조와 모든 알고리즘이 들어 있습니다. 실험을 실행하거나 결과를 집계하는 코드는 이 폴더에 두지 않습니다.

이 브랜치(`paper-faithful`)의 H5와 CSA는 대상 논문(Perez-Gonzalez et al., 2019)의 서술을 문면 그대로 따릅니다. 논문이 정하지 않은 부분은 아래 "논문이 정하지 않아 본 프로젝트가 정한 규칙"에 정리하였습니다.

## 파일별 역할

| 파일 | 내용 |
|---|---|
| `instance.py` | 인스턴스 자료 구조(`Instance`), 벤치마크 파일 파서(`load_instance`, `list_instances`, `parse_name`), 폴더 경로(`DATA_DIR`, `RESULTS_DIR`) |
| `schedule.py` | 해 표현(`Schedule`), 기계별 비용 계산(`machine_cost`, `job_tardiness`), 유효성 검사(`validate`) |
| `insertion.py` | 삽입 연산 `best_position`(BestPosition)과 `best_position_total`(BestPosition_Total) |
| `tiebreak.py` | 동점 처리 기준(`first`, `last`, `csum`, `random`), 기준을 바꾸는 `policy`, 팀의 기준 `BASELINE` |
| `h5.py` | 건설적 휴리스틱 H5: 구성(`construct`), 보정(`repair`), 개선(`improve`) |
| `csa.py` | 클론 선택 알고리즘 `csa_f`, `csa_t`와 그 구성 요소(GRASP, 이웃 연산자, VND, 적합도, 재선택) |
| `sa.py` | 개선 방법 `sa_t`와 냉각 방식(`geo`, `log`, `exp`), 온도 설정 |
| `milp.py` | Gurobi로 푸는 MILP 모형 `solve_milp` |
| `budget.py` | 실행 예산 `Budget`(시간 제한 또는 반복 횟수), 시간 제한 계산(`time_limit_seconds`), 실행 결과 `Result` |

## 모듈 사이의 의존 관계

```
instance  →  schedule  →  insertion  →  h5  →  csa
                                         └──→  sa
budget  →  csa, sa
schedule  →  milp
tiebreak  →  insertion, csa
```

화살표의 오른쪽 모듈이 왼쪽 모듈을 불러옵니다. `milp.py`만 `gurobipy`를 사용하고, 나머지 모듈은 Python 표준 라이브러리만 사용합니다.

## 공통 규칙

- 작업과 기계의 번호는 0부터 시작합니다. `p[i][j]`는 기계 i에서 작업 j의 가공시간이고, `s[i][j][k]`는 기계 i에서 작업 j 바로 다음에 작업 k를 처리할 때의 준비시간입니다.
- 해는 기계별 작업 순서 리스트(`Schedule.seqs`)입니다. 순서를 바꿀 때에는 반드시 `Schedule.set_machine`을 사용해야 저장된 비용이 함께 갱신됩니다.
- 각 기계의 첫 작업에는 준비시간이 없습니다.
- 탐색 알고리즘은 모두 `algorithm(inst, rng, budget)` 형태로 호출하고 `Result`를 돌려줍니다. `rng`는 `random.Random(seed)` 객체이며, 전역 난수 함수는 사용하지 않습니다.

## 동점 처리 기준

총 지연(또는 그 변화량)이 같은 후보가 여럿일 때 무엇을 고를지는 `tiebreak.py`가 정합니다.

- **논문이 정한 규칙**: BestPosition에서 삽입 전후 기계의 지연이 모두 0이면 완료시간 합이 작은 위치를 고릅니다(논문 5.2절). 이 규칙은 모든 기준에서 유지됩니다.
- **논문이 정하지 않은 동점**: 아래 네 기준 가운데 하나로 정합니다.

| 기준 | 총 지연이 같은 후보 가운데 고르는 것 |
|---|---|
| `first` | 살펴보는 순서에서 앞선 후보(작업 번호, 기계 번호, 위치가 작은 쪽) |
| `last` | 뒤쪽 후보(번호와 위치가 큰 쪽) |
| `csum` | 완료시간 합이 작은 후보, 그래도 같으면 앞선 후보 |
| `random` | 동점인 후보 가운데 하나를 같은 확률로 선택 |

- **팀의 기준은 `random`입니다**(`tiebreak.BASELINE`). 소규모 실험에서 CSA의 결과가 가장 좋았고, 번호 순서라는 임의의 선택을 피할 수 있기 때문입니다. 실험 결과는 `results/tiebreak/README.md`에 있습니다.
- **실험 실행기는 이 기준을 자동으로 적용합니다.** `experiments/run.py`에서 이름에 기준이 없는 방법(`h5`, `csa_t`, `sa_geo` 등)은 `random`으로 실행됩니다.
- **알고리즘 함수를 직접 부를 때에는 기준을 정해야 합니다.** `with tiebreak.policy("random", rng):`처럼 구간을 정하면 그 안에서 실행되는 H5와 CSA가 그 기준을 씁니다. 정하지 않으면 난수가 필요 없는 `first`로 동작합니다. 단위 테스트가 같은 입력에서 같은 결과를 확인할 수 있도록 이렇게 두었습니다.
- **기준이 적용되는 지점**: BestPosition, BestPosition_Total, GRASP(작업을 넣을 기계와 제한 목록의 순서), 내부 교환, 외부 삽입, 외부 교환입니다.
- **기준의 대상이 아닌 동점**: H5의 작업 순서(납기가 같은 작업), 지연이 가장 큰 작업과 기계의 선택, 재선택의 동점은 항상 번호가 작은 쪽을 고릅니다.
- **SA_t에는 자체 동점 결정이 없습니다.** 이웃을 무작위로 뽑기 때문이며, 기준은 출발해인 H5에만 영향을 줍니다.

## CSA의 세부 규칙

| 항목 | 구현 | 근거 |
|---|---|---|
| GRASP 제한 목록 | 삽입 후 총 지연이 작은 순서로 작업 5개 | 논문 6절의 "k개의 최선 작업"(k = 5) |
| 수용체 편집 | U[1, 2]회 반복하며, 확률 pmut(= 0)로 외부 교환을, 그렇지 않으면 외부 삽입을 적용. 논문의 연산자를 그대로 쓰므로 총 지연이 줄어들 때만 이동 | 논문 6절 |
| VND | 내부 교환, 외부 삽입, 외부 교환의 순서이며, 개선되면 첫 이웃으로 돌아감 | 논문 6절 |
| 이웃 연산자 | 지연 합이 가장 큰 기계 i*를 대상으로, 가장 좋은 이동을 총 지연이 줄어드는 경우에만 적용. 외부 연산자는 다른 기계를 무작위 순서로 시도 | 논문 6절 |
| 재선택 | 목적함수 오름차순으로 안정 정렬(같은 해의 반복을 허용). 가장 좋은 해를 먼저 고르고, 이후에는 후보 4개 가운데 이미 고른 해들과 가장 먼 해를 고름 | 논문 6절 |
| 우선도 | 부모보다 좋아진 클론은 100, 그렇지 않은 클론은 부모의 우선도에서 5를 뺀 값. 기억 집합의 해는 세대마다 5씩 감소 | 논문 6절(세부는 본 프로젝트가 정함) |
| 적합도 | 순위 점수의 비율과 우선도의 비율의 평균 | 논문의 식 (17) |
| 시간 제한 | n·m·t/2 밀리초(t = 30). 세대가 끝날 때마다 확인하며, 한 세대는 도중에 끊지 않음 | 논문 8절, Algorithm 5 |
| 파라미터 | \|Mu\| = 20, k = 5, Dprior = 5, Nc = 60, mutmax = 2, pmut = 0, x = 4 | 논문 8절 |

논문과 다르게 읽는 변형도 실행할 수 있습니다. 결과의 차이는 `results/README.md`가 안내하는 문서에 있습니다.

| 변형 | 내용 | 사용 방법 |
|---|---|---|
| 무작위 수용체 편집 | 수락 검사 없이 임의의 작업을 다른 적격 기계의 임의 위치로 옮김(Diana et al., 2015의 3.3.1절) | `receptor_random=True`, 실행기의 `csa_f_rnd`, `csa_t_rnd` |
| 제한 목록 5% | k를 미배정 작업의 5%로 읽음(Diana et al., 2015의 표 2). 올림하며 최소 1개 | `rcl_percent=True`, 실행기의 `csa_f_pct`, `csa_t_pct` |

`main` 브랜치에는 CSA의 세부를 Diana et al.(2015)에 맞춘 이전 구현이 남아 있습니다. 그 구현은 제한 목록 5%, 무작위 수용체 편집, 같은 해를 제거하는 재선택, 모든 동점에 완료시간 합을 쓰는 규칙을 기본으로 합니다.

## SA_t의 세부 규칙

| 항목 | 구현 |
|---|---|
| 출발해 | H5의 해 |
| 이웃 | 내부 삽입(같은 기계의 다른 위치), 외부 삽입(다른 적격 기계의 임의 위치), 외부 교환(다른 기계의 작업과 맞바꿈) 가운데 하나를 같은 확률로 생성 |
| 수락 | 총 지연이 늘지 않으면 수락하고, 늘면 exp(−Δ/T)의 확률로 수락 |
| 온도 설정 | H5 해의 이웃에서 양의 증가량 표본 100개를 모아, 평균 수락 확률이 0.80이 되는 온도를 T0, 0.01이 되는 온도를 Tf로 둠 |
| 냉각 단계 | K = 100단계. 사용한 시간의 비율에 따라 단계를 옮기므로, 시간 제한이 끝날 때 마지막 단계에 도달 |
| 시간 제한 | CSA와 같은 n·m·t/2 밀리초. 이웃을 하나 평가할 때마다 확인 |

냉각 방식은 다음과 같습니다. 세 방식 모두 T0에서 시작하여 마지막 단계에서 Tf에 도달합니다.

| 이름 | k단계의 온도 | 계수 |
|---|---|---|
| `geo`(기하) | T0·α^k | α = (Tf/T0)^(1/K) |
| `log`(로그) | T0 / (1 + b·ln(1 + k)) | b = (T0/Tf − 1) / ln(1 + K) |
| `exp`(지수) | T0·exp(−α·k^(1/n)) | α = ln(T0/Tf) / K^(1/n), n은 작업 수 |

비교와 진단을 위한 방식이 두 가지 더 있습니다.

- **`exp_cap`**: 계획서의 처음 설계대로 지수 냉각의 계수 α를 0.9로 제한한 방식입니다. Tf에 도달하려면 α가 대개 2–5여야 하므로, 이 방식의 종료 온도는 초기 온도의 20–30%에 머뭅니다. α가 1보다 커도 온도는 단조롭게 내려가므로 제한은 필요하지 않으며, 그래서 `exp`에서는 제한을 없앴습니다.
- **`none`**: 온도를 두지 않고, 총 지연이 늘어나는 이동을 받아들이지 않는 하강입니다. `experiments/diagnose_sa.py`가 사용합니다.

## 논문이 정하지 않아 본 프로젝트가 정한 규칙

| 규칙 | 위치 |
|---|---|
| 논문이 정하지 않은 동점은 팀의 기준(`random`)으로 처리 | `tiebreak.py` |
| H5의 그룹 안에서는 납기 오름차순(EDD)으로 처리(논문의 의사코드와 본문의 표기가 서로 어긋남) | `h5.construct` |
| 보정 단계에서 대상 작업의 지연이 0이거나 원래 기계에 작업이 하나뿐이면 이동하지 않음 | `h5.repair` |
| CSA_t의 초기 기억 집합은 H5 해 1개와 GRASP 해 19개 | `csa.csa` |
| 우선도의 하한은 0이며, 0에 도달한 해를 제거하지 않음 | `csa.csa` |
| 총 지연이 0인 해를 찾으면 즉시 종료 | `csa.csa`, `sa.sa_t` |
| 시간 제한에는 초기해 생성 시간을 포함 | `csa.csa`, `sa.sa_t` |
| SA_t의 이웃 구성, 온도 설정, 냉각 방식 | `sa.py` |

## 알려진 한계

- **CSA에는 같은 기계 안에서 위치를 옮기는 이동이 없습니다.** 모든 작업의 적격 기계가 1대뿐인 인스턴스에서는 작업을 다른 기계로 옮길 수 없으므로, CSA의 탐색은 지연이 가장 큰 기계 안의 교환만 남습니다. 논문의 서술을 따른 결과이며 고치지 않았습니다.
- **CSA는 시간 제한을 세대 단위로 확인합니다.** 한 세대가 오래 걸리는 환경에서는 시간 제한을 넘길 수 있습니다.

## 다른 폴더와의 관계

- `data`: `instance.py`가 `data/small`과 `data/medium`의 파일을 읽습니다. 경로는 `instance.py` 파일의 위치를 기준으로 계산하므로, `codes` 폴더를 어디에 두어도 동작합니다.
- `experiments`: 이 폴더의 알고리즘을 불러와 실행하고, 결과를 `results`에 기록합니다. `src`는 `experiments`를 불러오지 않습니다.
- `tests`: 이 폴더의 모든 모듈을 검증합니다. 모듈을 수정한 뒤에는 `codes` 폴더에서 `python -m pytest`를 실행하여 확인합니다.
