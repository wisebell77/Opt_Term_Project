# codes: 적격성과 준비시간이 있는 병렬기계 스케줄링

Perez-Gonzalez et al. (2019)의 CSA를 재현하고, SA 기반 개선 방법(SA_t)을 비교하는 프로젝트의 코드입니다. 범위와 구현 규칙은 상위 폴더의 `프로젝트 진행 계획서_Team4.docx`를 기준으로 합니다.

## 폴더 구성

| 폴더 | 역할 | 다른 폴더와의 관계 |
|---|---|---|
| `data/` | 벤치마크 인스턴스(소규모 3,840개, 중규모 5,760개) | `src`가 읽습니다. |
| `src/` | 자료 구조와 알고리즘(H5, CSA_f, CSA_t, SA_t, MILP) | `data`를 읽고, `experiments`와 `tests`가 불러옵니다. |
| `experiments/` | 실험 실행, 최적값 계산, 결과 집계, 수렴 곡선 | `src`를 불러오고, `results`에 기록합니다. |
| `results/` | 실험 결과 파일 | `experiments`가 기록하고 읽습니다. |
| `tests/` | 단위 테스트 | `src`와 `experiments`를 검증합니다. |

자료는 `data → src → experiments → results`의 방향으로 흐릅니다. 각 폴더의 `README.md`에 자세한 설명이 있습니다.

## 설치

Python 3.9 이상이 필요하며, 3.12와 3.15에서 동작을 확인하였습니다.

```bash
pip install -r requirements.txt
```

- `src`의 알고리즘은 `milp.py`를 제외하면 Python 표준 라이브러리만 사용합니다.
- `pandas`, `scipy`, `matplotlib`은 결과 집계(`experiments/analyze.py`, `experiments/convergence.py`)에 사용합니다.
- `gurobipy`는 MILP에만 필요합니다. 보유한 Gurobi 라이선스의 버전과 `gurobipy`의 버전이 같아야 하므로, 라이선스가 13 버전용이면 `pip install "gurobipy>=13,<14"`로 설치합니다.

## 실행

모든 명령은 이 폴더(`codes`)에서 실행합니다.

테스트 실행:

```bash
python -m pytest
```

실험 실행(소규모):

```bash
python -m experiments.run --size small
```

결과 집계:

```bash
python -m experiments.analyze
```

옵션, 여러 노트북에 나누어 실행하는 방법, 지표의 정의는 `experiments/README.md`에 있습니다.

## 방법 이름

| 이름 | 방법 |
|---|---|
| `h5` | 건설적 휴리스틱 H5 |
| `csa_f` | CSA, 초기 기억 집합을 GRASP만으로 생성 |
| `csa_t` | CSA, 초기 기억 집합에 H5의 해를 포함 |
| `sa_geo`, `sa_log`, `sa_exp` | SA_t의 기하, 로그, 지수 냉각 |
| `csa_f_k5`, `csa_t_k5` | GRASP 제한 목록의 크기를 5%가 아니라 5개로 읽는 CSA 변형(비교용이며 기본 실행에는 포함되지 않음) |
| `milp` | Gurobi로 구한 MILP의 해(소규모만) |

## 경로 규칙

코드에는 특정 컴퓨터의 절대 경로가 들어 있지 않습니다. `src/instance.py`가 자기 파일의 위치를 기준으로 `data`와 `results` 폴더를 찾으므로, `codes` 폴더를 통째로 옮기거나 다른 컴퓨터로 복사해도 그대로 동작합니다. 명령은 `python -m` 형식으로 `codes` 폴더에서 실행해야 `src`와 `experiments`를 불러올 수 있습니다.

## 진행 계획서와 달라진 부분

- 최상위 폴더 이름이 `codes`이고, 계획서의 `src/`, `experiments/`, `tests/` 구성을 그 안에 두었습니다.
- 실행 예산과 실행 결과를 다루는 `src/budget.py`, 최적값을 계산하는 `experiments/run_milp.py`, 수렴 곡선을 그리는 `experiments/convergence.py`를 추가하였습니다.
- CSA의 세부 규칙은 계획서의 표 8이 아니라 CSA의 원 논문인 Diana et al.(2015)을 따릅니다. 수용체 편집은 수락 검사가 없는 무작위 이동이고, 재선택에서는 같은 해의 반복을 허용하지 않으며, GRASP 제한 목록의 크기는 미배정 작업의 5%입니다. 항목별 근거는 `src/README.md`에, 조사 내용은 상위 폴더의 `reports/CSA 구현 근거 출처 조사.md`에 있습니다.

## 구현하면서 확인한 사항

코드를 구현하고 예비 실행을 수행하면서 확인한 내용입니다. 예비 실행은 인스턴스의 10분의 1만 사용하였으므로, 수치는 최종 실험에서 달라질 수 있습니다. 자세한 수치는 `results/pilot/README.md`에 있습니다.

1. **벤치마크의 다수는 최적 총 지연이 0입니다.** 소규모 3,840개 중 2,991개(77.9%)의 MILP 최적값이 0이고, τ = 0.2에서는 그 비율이 91.5%입니다. 중규모 예비 실행에서는 576개 중 557개의 최선값이 0이었습니다. 따라서 방법 사이의 차이는 소수의 인스턴스에서만 나타나며, RPD는 기준값이 0보다 큰 인스턴스에서만 계산합니다.
2. **CSA는 시간 제한을 모두 사용합니다.** 수용체 편집이 무작위 이동이어서 탐색이 스스로 멈추지 않으며, 총 지연이 0인 해를 찾은 경우에만 일찍 끝납니다. 예비 실행에서 시간 제한까지 실행된 CSA의 세대 수는 소규모에서 중앙값 283(최소 88), 중규모에서 중앙값 533(최소 15)이었습니다. 속도 보정 계수 c는 기본값 1로 두었으며, 세대 수가 적은 큰 인스턴스를 위해 c를 높일지는 최종 실험 전에 정해야 합니다.
3. **논문의 경향 가운데 일부만 재현됩니다.** CSA_t가 CSA_f보다 좋다는 경향과 τ = 0.4에서 모든 방법이 나빠진다는 경향은 논문과 같습니다. 반면 논문에서는 소규모 평균에서 CSA_f가 H5보다 나쁘지만, 본 구현에서는 CSA_f가 H5보다 훨씬 좋습니다.
4. **본 구현의 CSA는 원저자의 CSA보다 최적값에 더 자주 도달합니다.** Moser et al.이 공개한 원저자의 실행 결과(Zenodo, 10.5281/zenodo.4284100)에서 소규모의 최적 도달 비율은 CSA_t 84.4%, CSA_f 76.2%인데, 예비 실행에서는 98.2%와 96.9%였습니다. GRASP 제한 목록을 5개로 읽으면 99.4%와 99.5%가 되어 차이가 더 커지고 CSA_t와 CSA_f의 차이도 사라지므로, 5% 해석을 기본값으로 정하였습니다. 남은 차이의 원인은 확인하지 못했으며, 삽입 연산의 동점 처리처럼 어느 논문에도 적혀 있지 않은 세부가 후보입니다.
5. **SA_t(기하)는 예비 실행의 모든 인스턴스에서 기준값에 도달하였습니다.** CSA_t와 인스턴스별로 짝지어 비교하면 소규모에서 SA_t 우세 7개, 동률 377개이고 중규모에서 SA_t 우세 4개, 동률 572개이며, CSA_t가 앞선 인스턴스는 없었습니다. 지수 냉각은 작업 수가 많은 중규모에서 종료 온도가 목표보다 훨씬 높게 남아 성능이 떨어졌습니다.
6. **MILP는 3개 인스턴스에서 시간 제한에 도달하였습니다.** 소규모 3,840개 중 3,837개는 100초 안에 최적임이 증명되었습니다. 나머지 3개(`I_12_2_49_80_T04_R04_4`, `I_12_2_124_50_T04_R02_6`, `I_12_2_124_80_T02_R02_4`)는 `results/milp_small.csv`의 `optimal` 열이 False이며, 집계할 때에는 실행한 방법들의 최선값을 기준값으로 사용합니다. 다시 풀려면 해당 행을 지운 뒤 `--time-limit`을 늘려 `run_milp.py`를 실행합니다.
