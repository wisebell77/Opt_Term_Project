# codes: 적격성과 준비시간이 있는 병렬기계 스케줄링

Perez-Gonzalez et al. (2019)의 H5와 CSA를 구현하고, SA 기반 개선 방법(SA_t)과 비교하는 프로젝트의 코드입니다.

## 폴더 구성

| 폴더 | 역할 | 다른 폴더와의 관계 |
|---|---|---|
| `data/` | 벤치마크 인스턴스(소규모 3,840개, 중규모 5,760개) | `src`가 읽습니다. |
| `src/` | 자료 구조와 알고리즘(H5, CSA_f, CSA_t, SA_t, MILP) | `data`를 읽고, `experiments`와 `tests`가 불러옵니다. |
| `experiments/` | 실험 실행, 최적값 계산, 결과 집계, 진단 | `src`를 불러오고, `results`에 기록합니다. |
| `results/` | 실험 결과 파일 | `experiments`가 기록하고 읽습니다. |
| `tests/` | 단위 테스트 | `src`와 `experiments`를 검증합니다. |

자료는 `data → src → experiments → results`의 방향으로 흐릅니다. 각 폴더의 `README.md`에 자세한 설명이 있습니다.

## 설치

Python 3.9 이상이 필요하며, 3.12에서 동작을 확인하였습니다.

```bash
pip install -r requirements.txt
```

- `src`의 알고리즘은 `milp.py`를 제외하면 Python 표준 라이브러리만 사용합니다.
- `pandas`, `scipy`, `matplotlib`은 결과 집계(`experiments/analyze.py`, `experiments/convergence.py`)에 사용합니다.
- `gurobipy`는 MILP에만 필요합니다. 보유한 Gurobi 라이선스의 버전과 `gurobipy`의 버전이 같아야 하므로, 라이선스가 13 버전용이면 `pip install "gurobipy>=13,<14"`로 설치합니다.

## 실행

모든 명령은 이 폴더(`codes`)에서 실행합니다.

테스트 실행:

```bash
python -m pytest
```

실험 실행(소규모, 저장소의 결과를 만든 명령):

```bash
python -m experiments.run --size small --methods h5,csa_f,csa_t,csa_f_rnd,csa_t_rnd,sa_geo,sa_log,sa_exp,sa_exp_cap --reps 3 --workers 4 --tag full
```

결과 집계:

```bash
python -m experiments.analyze
```

옵션, 방법 이름, 지표의 정의는 `experiments/README.md`에 있습니다. 중규모 인스턴스 전체를 실행하는 순서는 `RUN_MEDIUM.md`에 따로 정리되어 있습니다.

## 방법

| 이름 | 방법 |
|---|---|
| `milp` | Gurobi로 구한 MILP의 최적해(소규모만) |
| `h5` | 건설적 휴리스틱 H5 |
| `csa_f` | CSA, 초기 기억 집합을 GRASP만으로 생성 |
| `csa_t` | CSA, 초기 기억 집합에 H5의 해를 포함 |
| `csa_f_rnd`, `csa_t_rnd` | 수용체 편집을 수락 검사 없는 무작위 이동(Diana et al., 2015)으로 바꾼 CSA |
| `sa_geo`, `sa_log`, `sa_exp` | SA_t의 기하, 로그, 지수 냉각 |
| `sa_exp_cap` | 지수 냉각의 계수를 0.9로 제한한 처음 설계(비교용) |

논문이 정하지 않은 동점은 팀의 기준인 `random`(동점인 후보 가운데 무작위 선택)으로 처리합니다. 실험 실행기는 이 기준을 자동으로 적용하며, 다른 기준은 `csa_t_first`처럼 이름에 붙여 실행합니다. 구현 규칙과 근거는 `src/README.md`에 있습니다.

## 경로 규칙

코드에는 특정 컴퓨터의 절대 경로가 들어 있지 않습니다. `src/instance.py`가 자기 파일의 위치를 기준으로 `data`와 `results` 폴더를 찾으므로, `codes` 폴더를 통째로 옮기거나 다른 컴퓨터로 복사해도 그대로 동작합니다. 명령은 `python -m` 형식으로 `codes` 폴더에서 실행해야 `src`와 `experiments`를 불러올 수 있습니다.

### 방법 사이의 비교

인스턴스별 평균 총 지연을 짝지어 비교한 결과입니다. 숫자는 (앞의 방법이 좋은 인스턴스 수 / 뒤의 방법이 좋은 인스턴스 수)이고, p값은 Wilcoxon 부호순위 검정의 값입니다.

| 비교 | 소규모 | 중규모 |

| CSA_f 대 CSA_t | 30 / 29 (p = 0.74) | 25 / 40 (p = 0.10) |
| CSA_t 대 무작위 수용체 편집 CSA_t | 15 / 37 (p = 0.0018) | 15 / 48 (p = 0.0077) |
| CSA_t 대 SA_t 기하 | 0 / 52 (p = 3.4e-10) | 0 / 62 (p = 7.6e-12) |
| 무작위 수용체 편집 CSA_t 대 SA_t 기하 | 0 / 33 (p = 5.4e-07) | 0 / 25 (p = 6.0e-08) |

### 확인한 사항

1. **벤치마크의 다수는 최적 총 지연이 0입니다.** 소규모 3,840개 중 2,991개(77.9%), 중규모 5,760개 중 5,616개(97.5%)입니다. 따라서 도달 비율로는 방법 사이의 차이가 작게 보이며, 차이는 기준값이 양수인 인스턴스의 RPD에서 드러납니다.
2. **방법의 순서는 논문과 같습니다.** H5, CSA_f, CSA_t의 순서로 좋아지고, τ = 0.4에서 모든 방법이 나빠집니다. 다만 동점 기준 `random`에서는 CSA_f와 CSA_t의 차이가 유의하지 않습니다.
3. **본 구현의 CSA는 원저자의 공개 결과보다 좋습니다.** Moser et al.이 공개한 원저자의 실행 결과(Zenodo, 10.5281/zenodo.4284100)에서 소규모의 최적 도달 비율은 CSA_t 84.4%, CSA_f 76.2%이고, 본 구현은 99.2%와 99.1%입니다. 동점 처리 기준이나 수용체 편집 방식을 어떻게 바꾸어도 본 구현은 98% 이상이므로, 이 두 가지는 차이의 원인이 아닙니다. 원저자의 코드가 공개되어 있지 않아 원인은 확인하지 못했습니다.
4. **동점 처리 기준은 H5의 결과를 바꾸지만, CSA에서는 `random`만 뚜렷한 차이를 냅니다.** H5의 삽입 결정 가운데 소규모에서는 약 30%, 중규모에서는 약 50%가 논문의 규칙만으로 정해지지 않습니다. 자세한 내용은 `results/tiebreak/README.md`에 있습니다.
5. **수용체 편집을 무작위 이동으로 바꾸면 CSA가 좋아집니다.** 논문의 서술대로 개선될 때만 이동하면 클론의 99.9%가 부모와 같은 해로 끝나서, 기억 집합 20개 가운데 서로 다른 해가 평균 2개가 되지 않습니다. 측정 결과는 `results/diagnostics/README.md`에 있습니다.
6. **SA_t는 CSA보다 좋습니다.** 기하 냉각은 가장 강한 CSA(무작위 수용체 편집)와 비교해도 좋은 인스턴스만 있고 나쁜 인스턴스가 없습니다. 중규모에서 기준값이 양수인 인스턴스의 RPD는 CSA_t가 28.7%, SA_t(기하)가 2.5%입니다.
7. **소규모에서 SA_t(기하)가 모든 실행에서 최적값에 도달한 것은 탐색 여유가 크기 때문입니다.** 실행의 약 80%는 출발해인 H5가 이미 최적이고, 나머지도 대개 시간 제한의 0.23% 지점에서 최적값을 찾습니다. 다만 하강만 하면 82.5%로 떨어지므로, 나빠지는 이동을 받아들이는 것이 필요합니다. 근거는 `results/diagnostics/README.md`에 있습니다.
8. **냉각 방식 세 가지는 목표 온도에 도달하도록 만들면 중규모에서 구별되지 않습니다.** 처음 설계에서는 지수 냉각의 계수를 0.9로 제한하였는데, 그러면 종료 온도가 초기 온도의 20–30%에 머물러 중규모에서 뚜렷하게 나빴습니다(64개 대 9개, p = 8.0e-11). 제한을 없앤 뒤에는 기하, 로그와 차이가 없습니다. 소규모에서는 기하 냉각이 조금 더 좋습니다.
9. **모든 작업의 적격 기계가 1대뿐인 인스턴스에서는 CSA가 약합니다.** 소규모에 459개가 있으며, CSA_t가 최적값을 놓친 실행의 비율이 이 유형에서 2.98%, 나머지에서 0.54%입니다. CSA에는 같은 기계 안에서 위치를 옮기는 이동이 없기 때문이며, 논문의 서술을 따른 결과이므로 고치지 않았습니다. SA_t에는 이 이동이 있습니다.

### 한계

- **반복이 3회입니다.** 원저자의 공개 자료는 5회입니다. 인스턴스 수가 많아 전체 평균은 안정적이지만, 인스턴스 하나의 평균은 거칩니다.
- **시간 제한을 쓰는 실험입니다.** 같은 시간 안에 수행하는 반복 횟수가 컴퓨터마다 달라서, 다른 컴퓨터에서 실행하면 수치가 조금 달라집니다. 방법 사이의 비교는 같은 컴퓨터에서 실행한 결과로 하였습니다.
- **중규모에는 MILP 최적값이 없습니다.** 작업 15–40개에서는 풀 수 없는 크기이며, 논문도 MILP를 소규모에만 사용하였습니다.
- **MILP는 3개 인스턴스에서 100초 안에 최적임을 증명하지 못했습니다.** 제한 시간 없이 다시 풀어 3,840개 모두 최적임을 확인한 결과가 `results/milp_small_unlimited.csv`에 있고, 목적함수값은 두 파일에서 같습니다.
- **Moser et al.의 공개 자료에는 MILP 최적값보다 작은 값이 3개 있습니다.** 소규모의 `I_8_3_124_80_T04_R04_3`, `I_8_4_49_50_T04_R04_8`, `I_8_5_49_50_T04_R02_2`에서 그 자료의 SA 값이 0인데, 증명된 최적값은 21, 3, 36입니다. 따라서 그 자료와의 비교는 참고로만 사용합니다.

## 진행 계획서와 달라진 부분

상위 폴더의 `프로젝트 진행 계획서_Team4.docx`와 다음이 다릅니다.

- 최상위 폴더 이름이 `codes`이고, 계획서의 `src/`, `experiments/`, `tests/` 구성을 그 안에 두었습니다.
- 실행 예산과 실행 결과를 다루는 `src/budget.py`, 동점 처리 기준을 다루는 `src/tiebreak.py`, 최적값을 계산하는 `experiments/run_milp.py`, 진단 스크립트를 추가하였습니다.
- CSA는 대상 논문의 서술을 문면 그대로 따릅니다(제한 목록은 작업 5개, 수용체 편집은 개선될 때만 이동, 재선택은 중복 허용). 계획서의 5.4절과 표 8은 CSA의 세부를 Diana et al.(2015)에 맞춘 이전 구현을 설명하며, 그 구현은 `main` 브랜치에 남아 있습니다.
- 논문이 정하지 않은 동점은 `random`으로 처리합니다. 계획서는 완료시간 합을 쓴다고 적었습니다.
- 지수 냉각의 계수 상한(0.9)을 없앴습니다. 계획서는 상한을 두고 예비 실험에서 확정한다고 적었습니다.
- 반복은 3회입니다. 계획서의 기본값은 5회이고, 3회는 계획서가 일정이 부족할 때의 대안으로 적어 둔 값입니다.
