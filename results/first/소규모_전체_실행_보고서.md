# 소규모 인스턴스 전체 실행 보고서 (`paper-faithful` 브랜치)

대상 논문: Perez-Gonzalez et al. (2019), *Constructive heuristics for the unrelated parallel machines scheduling problem with machine eligibility and setup times*.
구현한 방법: MILP, H5, CSA_f, CSA_t. 문제는 Rm | Mj, sijk | ΣTj이다.

## 1. 실행 조건

| 항목 | 내용 |
|---|---|
| 인스턴스 | `data/small` 3,840개(n = 6, 8, 10, 12 / m = 2, 3, 4, 5). `Small_Size_Instances.rar`와 바이트 단위로 같음 |
| MILP | 논문의 모형(식 (1)–(11), 비적격 기계는 매우 큰 가공시간), Gurobi 14, **시간 제한 없음** |
| H5 | 논문의 Algorithm 4 + 보정 + 개선(IP), 1회 실행(결정적) |
| CSA_f, CSA_t | 논문의 파라미터(\|Mu\|=20, k=5, Dprior=5, Nc=60, mutmax=2, pmut=0, x=4, t=30), 시간 제한 n·m·15 ms, 인스턴스당 3회 실행의 평균 |
| 실행 환경 | Python 3.13, 프로세스 5개 동시 실행 |
| 결과 파일 | `results/first/raw_small_full.csv`(H5, CSA), `results/milp_small_unlimited.csv`(MILP) |
| 집계 | `python -m experiments.compare_paper --raw results/first/raw_small_full.csv --milp results/milp_small_unlimited.csv` |

## 2. MILP 결과

- 3,840개 **모두 최적성이 증명**되었다. 최적값이 0인 인스턴스는 2,991개(77.9%)이다.
- 평균 풀이 시간은 1.13초이다. 가장 오래 걸린 인스턴스는 `I_12_2_49_80_T04_R04_4`(2,340초, 최적값 956)이다.
- 이전의 100초 제한 실행에서 증명하지 못한 3개(`I_12_2_49_80_T04_R04_4` 956, `I_12_2_124_50_T04_R02_6` 83, `I_12_2_124_80_T02_R02_4` 92)도 같은 값에서 최적으로 증명되었다.
- 논문의 모형과 비적격 변수를 뺀 강화 모형의 최적값은 모든 인스턴스에서 같았다.

## 3. H5와 CSA의 결과

| 방법 | 최적 도달 비율 | RPD(최적값 > 0인 849개) | 평균 실행 시간(초) |
|---|---|---|---|
| H5 | 81.1% | 118.3% | < 0.001 |
| CSA_f | 96.8% | 3.9% | 0.101 |
| CSA_t | 97.4% | 2.8% | 0.101 |

- 최적값이 0인 2,991개에서 평균 절대 차이는 H5가 2.87, CSA_f가 0.043, CSA_t가 0.048이다.
- CSA_t와 CSA_f를 인스턴스별로 비교하면 CSA_t 우세 70개, 동률 3,719개, CSA_f 우세 51개이다.
- CSA_f가 H5보다 나은 인스턴스는 714개, 나쁜 인스턴스는 30개이다.
- 어떤 방법도 MILP 최적값보다 낮은 값을 내지 않았다.

## 4. ARDI의 논문 비교

ARDI는 RDI = 100 × (값 − 최선값) / (최악값 − 최선값)의 평균이다. 최선값과 최악값은 인스턴스마다 방법들 중에서 정한다.
**논문은 19개 방법으로, 본 실험은 MILP, H5, CSA_f, CSA_t 4개 방법으로 계산하므로 최악값이 달라 ARDI의 절대 수치는 직접 비교할 수 없다.**
방법의 순서, 요인별 경향, H5에 대한 비율을 비교한다.

### 경향이 논문과 같은 부분
- 세 방법 모두 τ = 0.4에서 τ = 0.2보다 훨씬 나쁘다.
- p가 클수록 나쁘고, 준비시간이 U[1, 124]일 때 더 좋다.
- CSA_t가 CSA_f보다 낫다.

### 경향이 논문과 다른 부분
- **방법 순서.** 논문은 CSA_t < H5 < CSA_f이다(CSA_f가 H5보다 나쁨). 본 실험은 CSA_t < CSA_f < H5이다. 전체 비율 CSA_f/H5는 논문 1.21, 본 실험 0.08이다.
- **CSA의 규모.** 논문의 CSA_t/H5 비율은 요인 수준마다 0.24–0.49로 거의 일정하지만, 본 실험은 0.01–0.07이다. 본 실험의 CSA가 최적값에 훨씬 가깝다.
- **n의 효과.** 논문은 n이 클수록 CSA_f가 좋아진다(10.3 → 3.7). 본 실험의 CSA_t는 n = 6에서 0.12, n = 12에서 1.23으로 반대이다. 작은 n에서 CSA가 거의 최적이라 ARDI가 0에 가깝다.
- **m의 효과.** 논문의 CSA_f는 m이 클수록 나빠진다(2.98 → 10.23). 본 실험은 약하게만 같은 방향이다.
- **실행 시간.** 본 실험의 CSA 평균 실행 시간은 CSA_f, CSA_t 모두 0.101초이다. 논문은 CSA_t 0.175초, CSA_f 0.396초이며 CSA_f가 더 오래 걸린다.

## 5. 해석과 한계

- H5와 MILP는 논문의 서술대로 구현되었다. 난이도 요인(τ, p, 준비시간)에 대한 반응도 논문과 같다.
- CSA는 논문의 서술을 문면 그대로 따랐으나 논문보다 훨씬 강하게 수렴한다. 구현 차이로는 설명되지 않으며, 탐색 강도(C#과 Python의 속도 차이로 인한 세대 수, 논문의 종료 방식)가 원인일 가능성이 있다. 이 가설은 아직 검증하지 않았다.
- 논문이 규정하지 않은 세부(동점 처리, 보정 단계의 지연 0인 작업 처리, 외부 삽입에서 옮길 작업의 선택, 우선도 갱신, 지연 0 도달 시 조기 종료)는 본 프로젝트가 정한 규칙을 썼다. `src/README.md`에 정리되어 있다.
- 논문의 정렬 방향은 모순이다. Algorithm 4의 의사코드는 "non-increasing order of dj"이고 본문은 "EDD"이다. 본 구현은 EDD(납기 오름차순)를 썼다. 내림차순으로 바꾸면 H5의 최적 도달 비율이 81.1%에서 79.2%로 낮아진다.
- 논문의 ARDI와 같은 척도가 아니므로, 이 보고서의 비교는 경향의 비교이다.
- CSA는 3회 실행의 평균이며 시간 제한 기반 알고리즘이므로 컴퓨터와 동시 실행 프로세스 수에 따라 결과가 조금 달라질 수 있다.

## 6. 다음 단계

2. 비교용 변형(`csa_f_pct`, `csa_t_pct`: GRASP 목록을 5%로 읽음, `csa_f_rnd`, `csa_t_rnd`: 수용체 편집을 무작위 이동으로 함)도 같은 방식으로 집계한다.
3. 중규모 인스턴스에서도 같은 비교를 한다.
